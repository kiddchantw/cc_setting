# Add Conclusion

為筆記補上 `## 結論 / 解法` 區塊，寫成精簡摘要。

## 固定路徑設定

- **Vault 根目錄**: `/Users/kiddchan/Library/Mobile Documents/iCloud~md~obsidian/Documents/K88Dev/`
- **Inbox 目錄**: `{Vault 根目錄}0_inbox/`

## 使用模式

1. **對話提取模式**（有指定檔案 + 當前對話有明確問題/解法）：從當前對話 context 中提取問題和解法，寫入指定筆記
   - 例：「add conclusion SPF.md」（對話中剛討論完某個解法）
   - **優先使用此模式**：若對話中有具體的操作步驟、解法、或結論，直接從對話提取，不必依賴筆記原有內容
2. **指定檔案模式**（有參數，但對話中無明確解法）：讀取筆記本身內容，自動提取結論
   - 例：「補結論 admin.md」（純粹整理既有筆記）
3. **整批模式**（無參數）：掃描 `0_inbox/` 下所有 `.md`，找出缺少結論區塊的筆記
   - 例：「補結論」、「add conclusion」

## 排除清單（整批模式適用）

- `0_inbox/01promt/`
- 檔名以 `Untitled` 開頭的檔案
- `.base` 結尾的檔案
- `type: devlog` 的筆記（DevLog 有自己的 `## 關鍵收穫` 區塊）
- `type: zettelkasten` 的筆記（已有 `## 💡 核心概念` 區塊）

## 執行步驟

### Step 1：取得待處理檔案

- **整批模式**：掃描 inbox，篩選出**沒有** `## 結論` 或 `## 解法` 或 `## 結論 / 解法` 區塊的筆記
- **指定檔案模式**：直接處理指定的檔案

### Step 2：逐篇處理

對每篇筆記：

1. **讀取完整內容**
2. **判斷是否已有結論區塊**：若已有 `## 結論`、`## 解法`、`## 結論 / 解法` → 跳過
3. **決定結論來源**：
   - **對話提取模式**：直接從當前對話 context 提取問題描述和解法步驟，組成結論（忽略筆記原有內容的提取）
   - **指定檔案 / 整批模式**：從筆記內容判斷
     - 有具體指令、程式碼、設定步驟 → 提取為解法
     - 有明確的觀點、決策、結論 → 提取為結論
     - 內容太短或無法判斷 → 標記「無法提取」，跳過
4. **產生結論摘要**：1-3 句話，精簡扼要

### Step 3：呈現建議

用 AskUserQuestion 向用戶呈現：

```
📝 {檔案名稱}

建議結論：
---
## 結論 / 解法

{1-3 句摘要}
---
```

選項：
- **確認寫入**
- **跳過此篇**
- （用戶可選 Other 自行修改內容）

### Step 4：寫入

在筆記最後（`## 相關連結` 或末尾之前）插入 `## 結論 / 解法` 區塊。

使用 Edit 工具插入內容。

### Step 5：完成報告

- 補了 N 篇結論
- 跳過了 N 篇（已有結論 / 無法提取 / 用戶跳過）
