# Synthesize Concept Node

從 vault 裡多篇筆記中，讀取、歸納、萃取出一個**可複用的概念節點**，存入 `2_Resources/`，並在來源筆記補上雙向 wikilink。

## 核心目標

建立的概念節點必須回答這個問題：
> **「這些筆記背後，有什麼可重用的原則或模式？」**

命名原則：
- ✅ `大型檔案傳輸設計模式.md`（概念）
- ✅ `郵件認證基礎設施.md`（原則）
- ✅ `伺服器防禦縱深策略.md`（模式）
- ❌ `大檔案上傳3種方法.md`（工具清單）
- ❌ `SPF 設定筆記.md`（單一工具）

## 固定路徑設定

> 路徑變數定義於全域 `~/.claude/CLAUDE.md` 的 `Personal Knowledge Base` 區段。

- **Vault 根目錄**: `{Vault root}`
- **Resources 目錄**: `{Resources}`
- **Card Template**: `{Templates}/Zettelkasten Card Template.md`
- **搜尋排除**：`5_Pic/`、`Templates/`、`.claude/`

---

## 輸入模式判斷

從 `$ARGUMENTS` 判斷進入哪個模式：

- **主題模式**：輸入是關鍵字或主題描述（如「檔案上傳」、「郵件驗證」）→ 執行 **Step 1A**
- **指定模式**：輸入包含 `.md` 副檔名、或明確列出筆記名稱（如 `SPF.md, DKIM.md`）→ 跳過 Step 1A，直接進入 **Step 1B**

---

## 執行步驟

### Step 1A：主題模式 — 發現候選筆記

1. 從主題提取 **3-5 個搜尋關鍵字**（中英文各拆）
2. 搜尋整個 vault：

```bash
# 搜尋檔名
find "{Vault root}" \
  -not -path "*/5_Pic/*" \
  -not -path "*/Templates/*" \
  -not -path "*/.claude/*" \
  -name "*.md" \
  | xargs grep -il "{關鍵字1}\|{關鍵字2}\|{關鍵字3}"

# 搜尋 frontmatter keywords 欄位
grep -ril "keywords:.*{關鍵字}" \
  --include="*.md" \
  --exclude-dir="5_Pic" \
  --exclude-dir="Templates" \
  --exclude-dir=".claude" \
  "{Vault root}"
```

3. 合併去重結果，**排除**：
   - `_index_*.md`、`_Dashboard*.md`（索引/dashboard 不是來源筆記）
   - `_Archive/` 子目錄（已歸檔不納入新概念）
   - 已是 `type: zettelkasten` 且 `maturity: evergreen` 的筆記（已成熟概念不重複合成）

4. 呈現候選清單給用戶確認：

```
找到以下可能相關的筆記，請確認要納入合成的範圍：

| # | 筆記 | 路徑 | type | 摘要（前 2 行） |
|---|------|------|------|----------------|
| ✅ 1 | [[xxx]] | 2_Resources | devlog | ... |
| ✅ 2 | [[yyy]] | 0_inbox | zettelkasten | ... |
| ❓ 3 | [[zzz]] | 1_Projects/a126 | session | ... |

預設全選。請告訴我要排除哪幾篇，或直接說「確認」繼續。
```

> 若候選超過 10 篇，只列最相關的 10 篇，並說明總數。

---

### Step 1B：指定模式 — 直接確認範圍

1. 在 vault 中找到用戶指定的筆記（Glob 或 Grep 搜尋檔名）
2. 若找不到某篇，回報並詢問是否繼續
3. 列出確認清單，直接進入 Step 2

---

### Step 2：深度閱讀來源筆記

對每篇確認納入的筆記，依序讀取全文，特別關注：

- `## 💡 核心概念` / `## 結論` / `## 解法` / `## 關鍵收穫`（已萃取的精華）
- `## 📝 詳細說明`（完整內容）
- `keywords`、`tags`（分類線索）
- 筆記間是否有互相引用（wikilink）

閱讀後，在內部歸納：
1. **這些筆記有什麼共同模式？**
2. **它們解決的是同一類問題的不同面向嗎，還是同一問題的不同解法？**
3. **這個概念的「可複用邊界」在哪裡？**（即：什麼情況下你會用到這個概念？）

---

### Step 3：提案概念節點

在建立檔案之前，先向用戶提案：

```
📐 概念節點提案

**建議節點名稱**：`大型檔案傳輸設計模式.md`
（備選：`安全上傳架構原則.md` / `檔案上傳策略比較.md`）

**核心概念（草稿）**：
大型檔案上傳的核心挑戰是在網路不穩定的條件下保證完整性與使用者體驗。
主要解法分為三類：分塊上傳、斷點續傳、背景佇列，選擇取決於檔案大小與
使用情境。

**來源筆記**（{N} 篇）：
- [[大檔案上傳3種方法]] — 方法比較
- [[分塊上傳 Resumable Chunked Uploads - 黃金標準]] — 實作細節
- [[xxx]] — 實戰踩坑

**建議 maturity**：`seed`（新合成，尚未驗證）

---
請確認：節點名稱是否 OK？核心概念方向對嗎？或需要調整？
```

等用戶確認或修正後，再進入 Step 4。

---

### Step 4：建立概念節點

#### 4-1：產生 ID 與時間

```bash
date +"%Y%m%d%H%M%S"
```

#### 4-2：填寫節點內容

依照 Zettelkasten Card Template，填入：

**Frontmatter：**
- `id`: 當前時間戳
- `type`: `zettelkasten`
- `sub-type`: `null`
- `project`: `null`（概念節點通常是跨專案的通用知識）
- `sub-project`: `null`
- `tags`: 從來源筆記的 tags 歸納，取最具代表性的 1-3 個
- `keywords`: 合併來源筆記的 keywords，去重後取最核心的 4-8 個
- `aliases`: 列出這個概念的常見別名或中英文對照
- `status`: `active`
- `resolution`: `null`
- `maturity`: `seed`
- `updated`: 當下時間
- `completed`: `null`

**各 Section：**

- `## 💡 核心概念`：2-4 句話，精確說明「這個概念是什麼、解決什麼問題、核心原則是什麼」。用自己的話寫，不是抄來源。
- `## 📝 詳細說明`：展開說明，可包含：
  - 各方法/策略的比較（若來源筆記是同一問題的不同解法）
  - 實作要點、注意事項（從來源筆記提煉）
  - 不同情境下的選擇建議
- `## 🔗 相關連結`：列出所有來源筆記，加一句話說明各自貢獻了什麼：
  ```
  - [[大檔案上傳3種方法]] - 三種方法的橫向比較
  - [[分塊上傳 Resumable Chunked Uploads - 黃金標準]] - 分塊實作細節與最佳實踐
  ```
- `## 📚 參考來源`：列出來源筆記的外部來源（若來源筆記有填的話）
- `## 🏷️ 應用場景`：「什麼情況下你會想到來找這篇？」
- `## 💭 個人想法`：`- [ ] first read`（用戶自行填寫）

#### 4-3：存檔

存到 `{Resources}/{概念節點名稱}.md`。

存檔前確認同名檔案不存在：
```bash
find "{Resources}" -name "{概念節點名稱}.md"
```

---

### Step 5：回寫來源筆記（雙向連結）

對每篇來源筆記，在其 `## 🔗 相關連結` 區塊加入概念節點的 wikilink：

```markdown
- [[概念節點名稱]] - 此筆記所屬的概念節點
```

**操作規則：**
- 若來源筆記已有 `## 🔗 相關連結` 區塊 → 在區塊內新增一行
- 若來源筆記沒有此區塊 → 在檔案末尾加上此區塊再填入
- 若來源筆記已有 `[[概念節點名稱]]` → 跳過，不重複加

> ⚠️ 只新增連結，不修改來源筆記的其他任何內容。

---

### Step 6：完成報告

```
✅ 概念節點建立完成

**節點**：[[概念節點名稱]]
**路徑**：2_Resources/{概念節點名稱}.md
**maturity**：seed

**整合了 {N} 篇來源筆記：**
- [[xxx]] ← 已補上反向連結
- [[yyy]] ← 已補上反向連結

**建議後續：**
- 使用 [[概念節點名稱]] 的情況出現時，把它連入新的 session 或 devlog
- 當你再遇到相關案例，把新筆記也連進來 → maturity 會從 seed → linked
- 等概念穩定、無需再更新時，手動把 maturity 改為 evergreen
```

---

## 注意事項

- 概念節點**永遠存到 `2_Resources/`**，不進 inbox（它是已加工的知識，不需要再過濾）
- 不合併來源筆記的全文，只萃取**可複用的原則/模式/比較**
- 來源筆記**保持原位不移動**（搬移是 `obsidian-move-inbox` 的工作）
- 若來源筆記的 `maturity` 是 `seed`，合成後不自動升級它——留給用戶手動決定
- 若用戶只提供 1 篇筆記：提醒「概念節點通常需要 2+ 篇來源才有合成價值，你確定要繼續嗎？」
